# Local REPL protocol, version 1

The plugin and bundled agent share `repl-protocol`. The transport uses a subset of nREPL-shaped bencode messages with project-specific Java operations. It is not a claim of compatibility with arbitrary Clojure nREPL clients/middleware.

The agent binds loopback and publishes a private properties file containing `port`, `pid`, `token`, and `protocol`. A client reads this file, sends the token with every request, clones a session and checks `describe`'s protocol version and process ID before exposing a connected state. Tokens are not command-line arguments and are omitted from protocol debug messages.

Every request has `id` and `op`; session operations also have `session`. Every response retains these fields and ends with `status: [done]` or `status: [error, done]`. The client aggregates multipart output until `done`, including an error arriving after output. EOF completes outstanding requests exceptionally and closes the connection; requests are never replayed automatically.

The byte-oriented codec supports dictionaries, lists, integer IDs/metadata and UTF-8 strings. Statuses are lists on the wire. Boolean metadata uses string `true`/`false`. Frames are limited to 4 MiB total with nesting depth 32. Truncated frames, invalid UTF-8, malformed numbers, duplicate dictionary keys and excessive lengths fail the connection.

`describe` advertises the actual operation set from `ReplProtocol.OPS`:

- Control: `clone`, `describe`, `close`, `interrupt`, `capture/arm`, `capture/status`, `capture/disarm`, `capture/list`. These bypass the evaluation queue.
- Java: `eval` / `java-eval`, `imports/get`, `imports/add`, `vars/list`, `vars/drop`, `inspect`, `complete`, `analyze`, `session/reset`, `class-reload`.
- Spring: `bind-spring`, `list-beans`. The latter uses type metadata without initializing beans.
- Snapshots: `snapshot/list`, `snapshot/pin`, `snapshot/save`, `snapshot/load`, `snapshot/info`, `snapshot/export`, `snapshot/import`, `snapshot/import-file`, `snapshot/export-file`, `snapshot/diff`, `snapshot/delete`.
- Workbooks: `recipe/save`, `recipe/load`. Loading returns source; it does not evaluate it.
- Inspector: `inspector/start`, `inspector/page`, `inspector/push`, `inspector/back`, `inspector/bind`.
- Events: `events/start`, `events/stop`, `events/list`, `events/clear` (control operations, outside the evaluation queue).
- Tracing: `trace/configure`, `trace/list`, `trace/clear`.
- Debugger: `debug/claim`.
- Cases: `case/save`, `case/load`, `case/run`. CASE definitions are also returned by `snapshot/list`.

A connection owns at most eight sessions. Each session has a serial execution queue of 32 pending operations. The listener accepts at most eight clients. Client pending requests/writes are bounded; ordinary requests have a 180-second deadline. A 60-second `describe` heartbeat checks liveness and context epoch. These limits bound transport work; cooperative interruption cannot forcibly terminate arbitrary Java code that ignores interruption.

Snapshots accept an existing result `handle` or variable name in `expr`. The historical field name does not authorize expression evaluation. DATA load optionally takes a declared `type` and target `var`. Imported envelopes contribute only their data payload, not arbitrary type instructions. `inspect` pages collections with `offset`; `complete` takes source plus a cursor position and returns replacement anchors with completion text.

DATA envelopes are limited to 200 MiB of UTF-8 bytes including metadata. Inline `snapshot/import` (`name`, `json`) and `snapshot/export` (`name`) remain limited to 2 MiB and return a terminal error for larger JSON. `snapshot/import-file` and `snapshot/export-file` take `name` and `path` (an absolute local filesystem path) and return a short success/error response. The path is accessed by the application process: these operations require IDEA and the agent to share the filesystem; they are not remote file transfer. Export and repository writes are atomic, bounded and preserve previous files on failure. File import ignores stored type instructions. `snapshot/info` includes serialized size; listing reads headers without materializing payloads. The 4 MiB transport frame limit is unchanged.

`capture/arm` takes `point`, `name`, optional `case` (exact match), optional `type`, `ttl-ms` (default 300000, 1–1800000), `count` (default 1, 1–100) and `sample-every` (default 1, 1–10000). Returns `rule-id`. Up to 16 active rules per JVM; each belongs to its session. `capture/status` and `capture/disarm` take optional `rule-id` (latest own rule by default). `capture/list` returns owned rules as TSV: id, phase, point, name pattern, saved count, target count, sample interval, last saved name. Multiple saves use a sequence suffix or `${sequence}`. Active rules cannot target overlapping names. Sampling takes the first and then every Nth match; calls during that rule's save are skipped. Overlapping rules invoke their shared projection once. Serialization stays synchronous. Status adds `saved`, `count`, `sample-every`, `saved-name` to existing phase/size/duration/expiry metadata. Failed rules stop; there is no retry. Reset/close releases the owner's rules; context replacement expires/releases them; claimed saves can finish. The legacy six-argument Java `arm` helper retains its single-slot behavior for existing callers; protocol clients use independent rules.

`snapshot/diff` takes `before`, `after`, `offset` (0–9900) and `limit` (1–100). It compares DATA payloads without restoring declared Java types. `value` contains rows of escaped JSON-pointer path, change kind (`ADDED`, `REMOVED`, `CHANGED`), before preview and after preview, separated by tabs. Embedded control characters in paths/previews are escaped, so rows remain parseable. Additional fields: `has-more`, `scan-limited`, `changes-found`, `visited`. `changes-found` is an observed count, not a guaranteed total when more results or a scan limit exist. The 1,000,000-node/depth-128 budget is explicit. Array comparisons are positional; envelope metadata is excluded.

`complete` analyzes complete statements preceding the cursor without evaluating them. Anchors are offsets in the supplied source; the IDE maps current-cell offsets back into its document. Snapshot loading preserves explicitly declared generic element types in the bound Java variable.

The application context has a monotonically increasing epoch. A successfully captured replacement or close expires objects in bound sessions, clears LIVE pins and mix-ins, and requests interruption. Reset creates a shell against the current context; it never replays old snippets.

Legacy operation aliases are normalized in `ReplHandler.canonical`. Compatibility aliases do not make an unauthenticated 0.8 agent compatible with this client.

## Interactive tools (0.11.0)

`inspector/start` accepts an existing `handle`, `var` or session-owned numeric `event` ID. Navigation returns `value` as TSV rows: index, label, Java type, bounded preview, access error. `revision` identifies the current page; `inspector/push` requires that exact revision and a row `index`. `inspector/page` takes offset 0–9950 (50 children/page). `inspector/back` pops one level. `inspector/bind` takes `var` and optional `type`. The navigation stack is bounded to 32 levels. Root fields include `path`, `type`, `preview`, `offset`, `depth`, `has-more`, `scan-limited`. Values stay in the application; no arbitrary field expression/getter is evaluated. Snapshot save/pin accept `inspected=true` or `event` as alternatives to handles/variables.

`events/start` takes optional exact `label`; an empty label subscribes to all taps. `events/stop` unsubscribes without discarding existing values. `events/list` returns TSV rows: ID, epoch milliseconds, kind (TAP/TRACE/CASE), label, duration milliseconds, bounded preview. Additional fields: `subscribed`, `filter`, `dropped`. Retention is 128 references and five minutes per session, including idle expiry; no byte-size promise is made for live references. `events/clear` releases buffered events. Session close/reset and context replacement release subscriptions and rules.

`trace/configure` takes an exact binary `class` name, declared `method` name and `enabled=true|false`. It instruments all non-abstract/non-native/non-synthetic overloads of that name in the active application loader. Each session can trace eight methods, with a JVM-wide 16-class limit. JDK/agent infrastructure is excluded. `trace/list` returns class/method TSV; `trace/clear` removes the session's rules. A trace event contains live `arguments` (first 32), `result`, `exception`, `thread`, and nesting `depth`. Advice suppresses its own failures and preserves target return/exception behavior. Removed rules stop recording immediately; unused bytecode advice is subsequently removed.

`DebugBridge.checkTarget(session,pid)` validates the selected JVM/session before expression evaluation. IDEA's paused-frame evaluator calls `DebugBridge.capture(session,ticket,pid,value)` with a UUID ticket. This is a monitor-free transfer into a session-owned ticket store, bounded to 16 values and five minutes. After Resume, `debug/claim` consumes `ticket` once and binds the object to `var` (default `debugValue`), also initializing the Inspector. Tickets from another session, expired tickets and incorrect PIDs fail. No debugger protocol is tunneled through nREPL; IDEA provides breakpoints, stepping and lexical evaluation.

`case/save` takes `name`, input DATA `input`, expected DATA `expected`, optional input `type`, input `variable` (default `input`), and `code` (1–100000 characters). It persists a CASE envelope without evaluating it. `case/load` returns those fields. `case/run` executes one saved case in a fresh JShell against the current context, then compares the last result using the snapshot codec/diff budgets. It returns `outcome` (PASSED/FAILED/ERROR/CANCELLED/INCONCLUSIVE), `detail`, `duration-ms`, bounded `out`, optional result `event`, and diff fields. Temporary result serialization respects 200 MiB and is deleted afterwards. The client sequences up to 20 selected cases and runs them after `class-reload` only when redefinition succeeds. Interrupt targets the active case shell. Transport failures do not trigger automatic retries.

## Value previews and compiler checking (0.12.0)

Evaluation responses with a result handle, and Inspector page responses, add `view-data` and `view-limited`. Existing `value`, `values`, output, handle and navigation fields remain compatible. `view-data` is a display projection, never a Java deserialization payload: `v1` on the first line, followed by preorder TSV rows containing depth, kind, Base64 UTF-8 label, type and text. Kinds are `OBJECT`, `ARRAY`, `STRING`, `NUMBER`, `BOOLEAN`, `NULL`, `REFERENCE`, `LIMIT`, `ERROR`. `ValueTree` validates tree structure, kinds, depth (32), nodes (5000) and wire text (1 MiB). No class names from this payload are loaded by the IDE.

Automatic runtime projections use lower limits: 500 visited values, depth 6, 50 children per container and 131072 retained text characters. Truncation markers may add nodes beyond the visited-value count. Root strings use the text budget; nested strings are limited to 4096 characters. Instance fields are read directly, without getters or arbitrary `toString`. Known concrete JDK collections and standard Jackson nodes expose their logical children; custom/lazy collections and delegating JDK wrappers use fields. Cycles/repeated references and inaccessible fields are explicit. Preview failure does not replace a successful evaluation with an evaluation error. The real object remains available through its existing handle.

The IDE recognizes strict JSON object/array strings within the preview budget, preserves numeric literals and duplicate keys, and renders a collapsible tree plus two-space indentation. Malformed/oversized JSON stays text. Partial output is labelled; it is not a DATA snapshot or a promise of a reversible JSON encoding of arbitrary Java values.

`analyze` takes `code` (up to 100000 UTF-16 characters) and runs in the session's serial queue. It reads active snippet metadata and compiles a separate workspace against the cached application classpath. Its `ExecutionControl` never defines classes, invokes bytecode or reads live variable values. Annotation processors are disabled (`-proc:none`); normal initializers are replaced by default values when copying session variables. Source snippets are checked in workbook order without changing the real session. Unresolved declaration dependencies are checked after later workbook declarations have had a chance to resolve them.

The response has `diagnostics` as TSV rows: severity (`ERROR`/`WARNING`), start, end, message. Offsets are UTF-16 document positions with an exclusive end; messages have tabs/newlines flattened. Flags are `analysis-executed=false`, `analysis-limited`, `context-incomplete`. Limits are 100 diagnostics, 200 context declarations / 100000 context characters, 200 workbook snippets, and a cooperative five-second deadline checked between compiler operations. The deadline cannot forcibly stop an individual javac operation. Incomplete/limited analysis must not be displayed as a clean bill of health. The client debounces for 650 ms, keeps one active request plus the latest pending edit, and rejects stale document/session replies.


## 0.14 execution, reproduction and audit

`execution/policy` returns `execution-mode` (native default LIVE), `transaction-manager`, `timeout-ms`, `managers`, `limits`. `execution/configure` sets the mode LIVE/ROLLBACK/READ_ONLY, optional manager bean name and 100–120000 ms deadline (default 30000). `execution/preflight` accepts `code`, returning heuristic `warnings` and `limits` without execution. `eval`/`java-eval` and `case/run` accept overrides, with MCP forcibly supplying its own configured policy.

ROLLBACK and READ_ONLY use a synchronous REQUIRES_NEW transaction on the evaluation thread and always call rollback, including on success. READ_ONLY sets the transaction's hint. Missing/ambiguous managers fail before user execution. Inner independent transactions, other managers, async/reactive work and non-DB effects are outside this boundary. Timeout requests cooperative interruption, and starts after transaction acquisition. Results contain `execution-mode`, `transaction-manager`, `transaction-rolled-back`, `execution-duration-ms`, `side-effect-warnings`, `execution-limits`; timeout adds `execution-timed-out` and an error status. A rollback failure reports an unknown outcome rather than claiming rollback.

`case/save` additionally accepts `expected-exception` and `expected-message`; both empty keeps structural DATA comparison. A nonempty exception expects exact exception class and message. `case/run` may report CANCELLED for timeout; inspect outcome independently of transport success.

`reproduction/create` accepts `name`, existing input DATA `input`, optional `variable` (default input), `type`, and JSON-object string `metadata-json` (64 KiB). It uses the current session's last Java source/imports/result or runtime exception without evaluating again, and creates new independent input, expected, CASE, RECIPE, environment entries plus a DATA bundle index. The input must match the code's intended input, and earlier session dependencies are not auto-captured. Results include `bundle-id`, `case`, `input`, `expected`, `recipe`.

`reproduction/export-file`: `name` (bundle index), absolute runtime-side `path`. `reproduction/import-file`: absolute runtime-side `path`, optional new name prefix. Format `.sbrepl-bundle`: ZIP with `manifest.json` and `snapshots/0.json` through `4.json`; manifest format `sbrepl-reproduction`, schemaVersion 1, role/name/path/size/SHA-256 entries. Only DATA/CASE/RECIPE envelopes allowed, 200 MiB compressed/uncompressed ceiling, 64 KiB manifest, duplicate/unexpected paths rejected. All checks precede persistent imports; new unique names and CASE references are assigned. Import never evaluates the saved Java or materializes its declared types. Context metadata is evidence, never automatic authentication/profile/tenant restoration. SHA-256 is corruption detection, not sender authentication.

`audit/events` returns a bounded text preview of up to 100 current-file audit entries belonging to the session. Runtime and MCP audit JSONL are private under `~/.java-repl-audit` (`sb.repl.audit.dir` overrides for controlled testing); 4 MiB rotation, current + five retained files per PID/channel. Audit records phase, correlation ID, session/client, source and source hash, operation/context epoch and outcome/duration. Known secret patterns are redacted. Missing start audit prevents execution; missing completion audit reports an uncertain response. Capture saves are audited too. Audit is local and mutable by the host user, not a tamper-proof remote ledger.

MCP defaults to read-only tools; Java/state permission is the master gate. Separate write/delete/case/capture flags and optional per-tool allowlist further restrict it. MCP eval/CASE mode defaults to ROLLBACK, independent of the native session; tools cannot change the fixed MCP policy. Timeout default 30 s; session quota default 1000 calls (1–100000, interrupt exempt); result default 65536 characters (1024–65536). Responses retain truncation indicators and available handles. Secret masking is heuristic. Arbitrary Java is not sandboxed and can bypass narrower API-level permission boundaries; no package/bean/method security policy is claimed.

## CASE 2.0 (runtime 0.15, wire protocol remains 1)

`case/save` retains all old fields. Added string fields: `assertions-json` (object), `parameters-json` (array of 1–20 `{id,input,expected}` rows), `setup`, `teardown`, `imports`, `result-expression`, `tags`, `disabled` (`true`/`false`), `max-duration-ms` (1–120000). Code or result expression is required; all executable source totals at most 100000 characters. DATA references are validated on save and before execution. Empty parameters use the original input/expected pair.

Assertion configuration: `compareSnapshot`, `include`, `ignore`, `unordered`, `numericTolerance`, `timeToleranceMs`, `checks`. Paths use JSON Pointer with single-level `*`. Checks support `equals`, `contains`, `hasSize`, `matches`, `exists`, `notNull`, `isNull`, plus `match: all|any`. Unknown keys fail closed. Each JSON field is limited to 65536 characters. Comparison budget exhaustion never yields PASSED.

`case/run` executes parameter rows sequentially, in separate JShells and selected transaction boundaries, with one request deadline. Rows stop on ERROR/CANCELLED. Output retains legacy single-row fields plus `rows-total`, `rows-completed`, `run-id`, `rows-json` (bounded per-row reports). Disabled cases return SKIPPED without running code. Cleanup is best effort and skipped after interruption. Each actual result has a runtime event for inspection.

- `case/list`: TSV name, tags, disabled, parameter row count; no execution.
- `case/run-batch`: `names`, newline-separated, 1–20 distinct cases / max 100 parameter rows. Loads and validates all definitions before execution; shares one deadline and stops on ERROR/CANCELLED. `outcome`, `cases-completed`, `cases-total`, TSV name/outcome response.
- `case/result`: `name`, optional zero-based `row`. Reads this session's last report, never reruns. Keeps up to 20 case results; reset/context invalidation clears the cache.
- `case/export-junit`: `name`, optional `package` (default reproduction), `class` (default ReproductionTest), `file`. No file selects the manifest; file selects one exact generated text file (<=65536 characters). No Java execution or filesystem writes. Requires a saved explicit input type and result expression; validates Java syntax, not application types.
- `case/export-junit-file`: same name/package/class, plus destination `path`; writes an atomic ZIP containing Java tests, portable assertion source, JSON resources and README. Total uncompressed size <=16 MiB. Honors `execution-mode`, `transaction-manager`, `timeout-ms` for generated tests. Not exposed as an MCP filesystem-write tool.

MCP adds case list, batch, result and JUnit export tools (43 tools total). Batch requires the existing CASE execution permission and receives the fixed MCP execution policy. JUnit preview uses that policy for generated source, but executes nothing and is available in read-only mode. Generated source/data may be redacted or truncated by MCP output policy; use IDE ZIP export for complete fixtures. Reproduction bundle v1 still supports one frozen input/expected pair; parameterized/rebound CASE export is rejected instead of silently omitting DATA dependencies.

## 0.16 notebook, workspace and snapshot revisions

Wire protocol version remains `1`. New capabilities appear in `describe`; older clients can continue using the current v1 snapshot envelope.

- `notebook/symbols {code}` returns `declared-symbols` (newline-separated candidate declarations), `conservative`, `analysis-executed=false`. Uses JShell `sourceToSnippets` without installing or executing declarations; source ≤1 million characters, ≤200 snippets examined. MCP source limit remains 100000. Symbol relationships are conservative, not alias/async/bean-state tracking. See the [JDK API contract](https://docs.oracle.com/en/java/javase/17/docs/api/jdk.jshell/jdk/jshell/SourceCodeAnalysis.html#sourceToSnippets(java.lang.String)).
- `snapshot/versions {name, offset=0, limit=20}` returns `versions-json` (array), `total`; limit 1–100, nonnegative offset. Rows contain SHA-256 `version`, `current`, capture/record times, kind, size and available provenance. Listing reads bounded metadata; opening a historical file verifies its SHA.
- `snapshot/provenance {name, version?}` returns JSON in `value`. Empty version means current. `snapshot/restore-version {name, version}` makes a new current revision with `restoredFrom`; it copies JSON without application codecs or code evaluation.
- `snapshot/load` gains optional `version`; it materializes that immutable DATA revision, leaving current unchanged. Response adds `snapshot`, `snapshot-version`, `restorable` alongside `var`/`type`. Normal DATA materialization can execute DTO constructors.
- Current snapshot files remain `v1/<application-hash>/<name-hash>.json`. Immutable files live under `versions/<name-hash>/<sha256>.json`. New writes serialize first, then archive and atomically replace the current file under JVM and cross-process repository locks. At most 100 versions/name; explicit delete purges all. No auto-pruning. Legacy current files are archived on first overwrite.
- `workspace/context {}` returns observed context JSON in `value` and current `imports`. `workspace/export-file {path,state-path}` reads an existing UTF-8 workspace metadata JSON from the JVM filesystem, adds live imports/observed environment/variable type inventory, and exports current DATA/CASE/RECIPE plus historic DATA revisions referenced by bindings. No evaluation occurs.
- `workspace/import-file {path,prefix}` stages and validates every ZIP entry before importing new names. Returns JSON strings `names-json` (old name to new current name), `bindings-json` (old name + newline + old version to imported name), `versions-json` (new name to new version SHA). CASE input/expected and parameter-row references are remapped. Arbitrary Java/RECIPE string literals are not rewritten. This runtime operation never opens the IDE editor, materializes DATA or runs imports/HTTP/CASE.
- Workspace format: ZIP `manifest.json`, `workspace.json`, `objects/<sha256>.json`. Manifest format `sbrepl-workspace`, `formatVersion:1`, `workspaceSha256`, `entries:[{name,version,path,current,kind}]`. Duplicate, unreferenced, traversal and bad-checksum entries fail. ZIP and cumulative uncompressed size ≤200 MiB, metadata files ≤8 MiB, ≤1200 snapshot entries. Import creates fresh names, protects existing snapshots, and removes new files on ordinary commit failure. It does not promise atomic recovery from process death midway through a multi-file import.
- `inspector` responses add opaque `bookmark-path` (URL-base64 child labels separated by dots); `inspector/restore-path {var,path}` navigates a current named variable without eval. Missing/ambiguous labels, depth over 31 or scans over 10000 children fail. Bookmarks describe a path, not an object identity guarantee.

IDE-only workspace metadata `formatVersion:1` stores `notebook`, `imports`, `bindings`, `bookmarks`, `httpRequests`, `unrestorableVariables`, `environment`, optional `transcript`. Notebook state includes stable IDs, source, last executed hash, sequence, status, time/duration, bounded output and conservative symbol evidence. Imported/checkpoint evidence becomes stale; objects, credentials, profiles and bean state are never automatically revived. Project recovery checkpoints use private files under the IDEA system directory, outside VCS. The portable document contains application data and is not encrypted.

MCP adds `repl_snapshot_versions`, `repl_snapshot_provenance`, `repl_notebook_symbols` as read tools; `repl_snapshot_restore_version`, `repl_workspace_export`, `repl_workspace_import` require execution **and** snapshot-write permission. Workspace paths refer to the target JVM filesystem. The 49-tool catalog remains session-gated, audited, bounded and subject to existing per-tool permissions and quotas.

## 0.18 recorded method calls

Protocol version remains `1`; these additive operations are advertised by `describe`. They are native IDE/runtime operations. Since 0.20, a separate project-scoped MCP recording adapter also exposes the IDE's shared frozen recording; it does not borrow the IDE evaluator.

- `trace/record {classes}`: newline-separated 1–8 exact application class names. Instruments concrete declared methods (all overloads); no constructors, abstract/native/synthetic methods or JDK/agent infrastructure. At most 64 method names/class and 16 classes across all sessions/legacy trace rules. Stop an active recording before replacing it. A failed setup restores prior rules.
- `trace/history {}`: control operation available during evaluation. Returns recording UUID, `active`, `classes`, `context-epoch`, `revision`, preview `bytes`, first limit-rejection count `dropped`, and newline-separated `RecordedCall.header().encode()` in `value`. Headers omit input/output/exception payloads.
- `trace/call {recording,call-id}`: control read for a call's frozen entry/exit preview; `value` is `RecordedCall.encode()`. `call-id` is distinct from the transport request's `id`. Old recording UUIDs are rejected.
- `trace/stop {}`: control operation; stops new entries and removes this session's class recording instrumentation. Existing tickets can finish and update retained call data. Legacy method traces are independently owned. `trace/clear`, reset, connection close or context invalidation releases the runtime recording; clients retain only previews they already downloaded.

`call-v1` has 20 TSV fields: marker, recording UUID, invocation id, parent id, root id, class, method, JVM descriptor, newline-separated parameter names, thread id, thread name, start milliseconds, duration nanoseconds, status, summary, input, output, exception, live event id, revision. Textual fields class/method/descriptor/names/thread-name/summary/input/output/exception are standard UTF-8 Base64. Status is RUNNING/SUCCESS/ERROR; offline files also use INCOMPLETE. Preview fields are `ValueTree` wire strings. Headers and values must be merged by recording + call id + monotonic revision. Calls retain entry-order identity even when exit order differs. Missing or cross-thread parents are invalid; unobserved methods are omitted and async threads begin new roots.

Limits: 200 retained calls, 32 MiB UTF-16 preview payload budget/session, at most 64 active observed stack levels, first 32 arguments, 262144 encoded characters/preview. Standard automatic value presentation applies (500 nodes, depth 6, 50 children, 131072 total text characters). Limit completion pauses capture without evicting existing parents. Later suppressed calls are not counted individually. No application getters/custom serializers or overridden exception-message methods are invoked. Preview work is synchronous and adds overhead; concurrent mutation is not an atomic object snapshot. These are display records, not DATA materializations or CPU profiles. Optional `event` points into the existing 128-item/five-minute live cache, whose objects can change after recording.

IDE archive: UTF-8 JSON `.sbrepl-recording`, `format:"sbrepl-recording",version:1,id,epoch,calls:[encoded full calls],sources:[{className,fileName,text,sha256,methods}]`. `methods` maps method-name + JVM descriptor to source character offset. Up to 64 MiB/file; 8 captured Java sources, 1 million characters/source and 4 million total. Source paths are not imported or written; the hash detects corruption, not authenticity. RUNNING calls export as INCOMPLETE. Source is captured at recording start and is not verified against loaded bytecode. Opening a changed/missing source uses a read-only LightVirtualFile. Import validates limits, graph identities, descriptors, preview trees and source hashes before replacing the displayed recording; it executes no Java and restores no JVM frame. Save files use a private atomic write. Workspace bundles do not include these separate recordings.


## MCP recording access (0.20)

The MCP registry now has 60 tools. The 11 `repl_recording_*` tools use IDE-local `recording/*` adapter operations, **not new nREPL wire operations**. The runtime remains protocol version 1. The adapter copies RecordingController state on the EDT and decodes, filters and compares immutable evidence off the EDT. Existing evaluation tools keep their independent NreplMcpBackend session.

Sharing defaults off (Share IDE recordings with MCP). Read tools and one per-client frozen reference pin require sharing; select also requires execution/state changes; start/stop additionally require captureChanges. The tool allowlist, localhost token authentication, quota, output budget and audit apply. Closing a client clears its reference without clearing/stopping the IDE recording. Queued UI changes are cancelled when access closes.

Each response uses typed structuredContent plus equivalent text JSON, per the [MCP tools contract](https://modelcontextprotocol.io/specification/2025-11-25/server/tools). Base64 RecordedCall/ValueTree wire strings and live event/handle identities are not exported. Known secrets are masked in decoded trees and whole source text **before** search, summary, diff and paging. Redaction is heuristic and can be disabled by the user's existing switch.

`recording/status` gives available, recording, view, active/starting/offline, contextEpoch, selected, callCount, downloadedCalls and complete. Other reads require the recording ID and optionally the view; view hashes active/offline state and each call's revision/download state. A changed view fails instead of mixing pages. Status/start/stop/select reply with state. Start requires expected=current-ID or "none", classes=1–8 newline-delimited exact names; stop/select compare IDs atomically on the EDT. Start/stop wait for runtime acknowledgement, not for all values to download.

`calls` returns nodes (parent/root/depth/contextOnly/collapsed/hiddenCalls/hiddenErrors and decoded summaries). Filters: query, errors-only string boolean, root/focus/thread, min-duration-ms, ordered from-ms/to-ms pair; collapsed accepts comma-separated call IDs. `timeline` returns spans with the same filters except folding, originEpochMs and no inferred async edges. Pagination uses offset and limit (default 20, max 50), totalRows and nextOffset; pages may be shortened to fit the result budget.

`call` takes call ID and returns signature/descriptor, timing/status, sourceAvailable, breadcrumb/children IDs and previous/next/nextError. `values` takes call, part=input/result/exception and an optional child-index path ("" or /0/2). The node contains kind/type/label/text, childCount, textLength and nextTextOffset. offset/limit page immediate children; text-offset/text-limit page redacted scalar text (default 1024, max 4096 UTF-16 chars). `source` pages redacted captured source (default 2048, max 4096 chars), fileName/class, original methodLine and capturedSha256; no arbitrary path read.

`pin` keeps one downloaded frozen call per MCP session and returns reference. `compare` requires after and exactly one of before=current-recording-call-ID or reference=this-client-pin-ID. A reference survives IDE recording replacement but expires with its client. Differences are paged, structural and bounded (2000 changes), with partial/comparisonTruncated/textTruncated and explicit redactedComparison. Limited, missing, running or masked evidence cannot establish full equality.

Shared recordings still obey 200-call / 32 MiB capture and 64 MiB saved-file limits. MCP startup still needs a connected runtime; opening an offline recording in the running IDE makes it visible while MCP is active. No new filesystem import/export, GUI layout-control tools or SSE notification stream are introduced. Full schemas/examples: [agent instructions](docs/claude-repl-instructions.md#ide-felvételek-és-gráf-mcp-n-020).

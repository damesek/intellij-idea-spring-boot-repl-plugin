# MCP az AI-agentek számára - 0.13.0

Claude-hoz a [0.13.2 használati és kapcsolódási útmutatót](../claude-repl-guide-hu.md), valamint a [Claude-nak átadható munkautasítást](../claude-repl-instructions.md) használd. Az alábbi ellenőrzési rész a korábbi 0.13.0 állapotot rögzíti; a későbbi sikeres Gradle-build, tesztek és Plugin Verifier eredménye a [0.13.1 jelentésben](IDEA_2025_2_0_13_1.md) található.

A plugin **MCP** lapjáról a **Start MCP** gomb helyi HTTP-kiszolgálót indít. A munkafüzet **MCP** gombja erre a lapra vált. Külön adapterprogramot nem kell telepíteni.

## Használat

1. Indítsd az alkalmazást a szokásos Run Configurationből, bekapcsolt **Enable Spring Boot REPL** opcióval. Várd meg a REPL kapcsolatot; a `READY` állapot jelzi a kész Spring contextet.
2. Nyisd meg a **Spring Boot REPL → MCP** lapot. A port alapértéke `0`: szabad helyi portot választ. Megadhatsz állandó portot is.
3. Az **Allow Java execution / state changes** kezdetben be van kapcsolva, az **Allow HotSwap** ki van kapcsolva. A kiválasztott jogokat a **Start MCP** rögzíti az adott futásra.
4. Nyomd meg a **Copy client config** gombot. A másolt JSON a helyi MCP-klienshez szükséges URL-t és `Authorization` fejlécet tartalmazza. Illeszd be olyan kliens MCP-beállításába, amely támogatja a Streamable HTTP-t és az egyéni HTTP-fejléceket. A kliens saját konfigurációs formátuma eltérhet; a másolt URL és fejléc értékét használd.
5. Kérd az agentet például erre: „Kérd le a REPL állapotát és a beanek listáját. Ellenőrizd a `ctx.getBeanDefinitionCount()` kódot futtatás nélkül, majd értékeld ki.”

A másolt beállítás szerkezete (a port és a token csak szemléltető):

```json
{
  "mcpServers": {
    "spring-boot-repl": {
      "url": "http://127.0.0.1:PORT/mcp",
      "headers": { "Authorization": "Bearer GENERATED_TOKEN" }
    }
  }
}
```

A szerver csak `127.0.0.1` címen figyel. Minden indítás új hozzáférési tokent generál; ezért újra kell másolni a beállítást. A token a vágólapra másolt konfiguráció része, a panel állapotában és a naplóban nem jelenik meg. Felhőben futó, helyi HTTP-elérés nélküli kliens közvetlenül nem tud kapcsolódni.

## Elérhető eszközök

| Terület | Eszközök |
| --- | --- |
| Állapot, előzetes ellenőrzés | `repl_status`, `repl_list_beans`, `repl_analyze`, `repl_complete`, `repl_variables`, `repl_imports` |
| Java és session | `repl_eval`, `repl_interrupt`, `repl_reset`, `repl_bind_spring`, `repl_add_imports` |
| Objektumböngésző | `repl_inspect`, `repl_inspect_page`, `repl_inspect_push`, `repl_inspect_back` |
| Snapshotok | `repl_snapshot_list`, `repl_snapshot_info`, `repl_snapshot_diff`, `repl_snapshot_save`, `repl_snapshot_pin`, `repl_snapshot_load`, `repl_snapshot_delete`, `repl_snapshot_import`, `repl_snapshot_export` |
| Trigger, esemény | `repl_capture_arm`, `repl_capture_status`, `repl_capture_disarm`, `repl_events`, `repl_events_start`, `repl_events_stop` |
| Teszteset, frissítés | `repl_case_save`, `repl_case_load`, `repl_case_run`, `repl_reload` |

A `tools/list` csak az engedélyezett eszközöket adja vissza. A tiltást a szerver a `tools/call` során is ellenőrzi. Ha a Java-futtatás kapcsoló ki van kapcsolva, az állapotlekérés, kódellenőrzés és a már mentett adatok olvasása marad elérhető. Az explicit objektumböngészés is futtatási jogot kér, mert például egy saját kollekció hozzáférő metódusát meghívhatja. A HotSwap külön engedélyt is igényel.

## Egy munkamenet

Az AI-kliens inicializálásakor saját nREPL-kapcsolat és JShell-session jön létre. Az IDE-ben és a többi MCP-sessionben létrehozott változók és objektumhandle-ök nem keverednek. A `ctx` az alkalmazás Spring contextjére mutat. Ha a kliens még a Spring indulása alatt kapcsolódott, a `repl_bind_spring` utólag köti be a `ctx` változót.

Például: `repl_eval` → `{ "code": "var input = java.util.List.of(1, 2, 3); input" }`. A válaszban kapott `handle` átadható a `repl_inspect` vagy `repl_snapshot_save` eszköznek. `repl_analyze` a kódot futtatás nélkül ellenőrzi, az aktuális session típusaival és importjaival. A `repl_capture_arm` egy már alkalmazáskódba írt SnapshotHelper trigger következő találatát várja; az alkalmazás üzleti folyamatát önmagában nem indítja el.

A Spring beanek, az alkalmazásra/adatbázisra gyakorolt hatások és a tartós DATA snapshotok közösek. A külön session és a `repl_reset` nem jelent tranzakciós visszaállítást vagy homokozót. A mentett teszteset futtatása is hozzáférhet a valódi beanekhez. A debugger léptetése és az editor műveletei továbbra is az IDE-ből érhetők el.

## Kapcsolat és eredmények

- MCP-változatok: `2025-11-25`, `2025-06-18`, `2025-03-26`. A szerver az `initialize` kézfogást és a `MCP-Session-Id` fejlécet használja. A 2026-os, kézfogás nélküli protokoll nincs implementálva.
- Streamable HTTP, JSON-RPC 2.0, JSON-válaszok; nincs SSE-eseményfolyam vagy stdio-folyamat. `GET /mcp` válasza 405, az inicializáló értesítésé 202, `DELETE /mcp` lezárja a megadott sessiont.
- Legfeljebb 4 MCP-session. 30 perc MCP-inaktivitás után a session lejár; folyamatban lévő hívás közben nem jár le. Egy session legfeljebb 4096 különböző kérésazonosítót fogad.
- Sessionönként egy normál eszközhívás futhat; a megszakítás külön érkezhet. A kliens `notifications/cancelled` üzenete csak a hivatkozott, saját futó hívást szakítja meg.
- Nincs automatikus újracsatlakozás vagy kódújrajátszás. Az ismételt kérésazonosító hibát kap. Bizonytalan kimenetelű szállítási hiba/időtúllépés lezárja a sessiont; előbb ellenőrizd az alkalmazást, majd csatlakozz újra.
- A **Stop MCP**, a REPL-kapcsolat cseréje/megszakadása és a projekt bezárása leállítja az elérést. A sessionváltozók és LIVE pinjeik felszabadulnak, a DATA snapshotok megmaradnak. Kontextusváltás után a runtime explicit session resetet kér.
- A válasz `content` szöveges JSON-t és `structuredContent` objektumot ad; az alkalmazáshibát `isError: true` jelzi. A Java-objektumok/JSON-sztringek `preview` fát, típusokat és elérhető handle-t adnak. Az értékek csak korlátozott megjelenítési másolatok.
- A listák `offset`/`limit` paraméterrel lapozhatók (alap 50, maximum 100 sor), és `nextOffset` értéket adnak, ha van folytatás. A kérés maximum 256 KiB, a válasz maximum 512 KiB. A csonkolást `truncatedFields`, `truncated` vagy a runtime `view-limited` mezője jelzi.
- A runtime 200 MiB-os snapshotkorlátja változatlan. Az MCP kis JSON importot/export-előnézetet támogat; teljes nagy fájlhoz az IDE snapshot fájlexportját használd.

A protokoll alapja a [hivatalos MCP Streamable HTTP leírás](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports) és az [MCP eszközmodell](https://modelcontextprotocol.io/specification/2025-11-25/server/tools).

## Ellenőrzés

Helyi ellenőrzés, 2026-09-14:

| Ellenőrzés | Java 17 | Java 21 |
| --- | --- | --- |
| Teljes runtime regresszió | 98 sikeres | 98 sikeres |

| Csomagolt agent: szerkezet, Spring-indulás/profilok, Boot JAR osztályazonosság | 3 sikeres, 1 socketteszt kihagyva | 3 sikeres, 1 socketteszt kihagyva |
| Nagy snapshot | 1 sikeres | 1 sikeres |

Összesen **165 sikeres teszt Java-verziónként**. A JUnit 4 összesítője 64 plugin-tesztesetet jelez, mert az assumption miatt kihagyott HTTP-próbát is beleszámítja. A külön JDI/socket integráció itt nem futott.

A 22 új MCP-tesztesetből 21 futott sikeresen, 1 az élő HTTP socketpróba. Az ellenőrzött esetek között van az inicializálás, hitelesítés és Origin/Host ellenőrzés, jogosultságok közvetlen hívás elleni védelme, sessionkvóta/lejárat, leállítás inicializálás közben, megszakítás, párhuzamos hívás, ismételt azonosító, hibás és túlméretes JSON, lapozás, Unicode-válaszkorlát, gombok és konfigurációmásolás. A három integrációs eset a valódi `NreplClient`, bencode és JShell/runtime kóddal, csöves adatátvitellel ellenőrzi a külön sessionöket, futtatás nélküli elemzést, objektum/JSON-előnézetet, snapshot-visszatöltést, capture élesítést és az indulás után bekötött Spring contextet.

Tiszta kimeneti könyvtárakból lefordult a teljes Kotlin plugin, Java runtime, megosztott protokoll, bridge és a tesztforrások. A helyben elérhető függőségekkel végzett futások Spring Boot 3.2.0 / Spring 6.1.1 / Jackson 2.15.3 verziókat használtak; a Gradle-ben deklarált Spring Boot 3.5.6-os tesztkör ezen a gépen nem futott le. A két IDE-készlettel végzett külön osztálybetöltési próba sikeres: **IC 2024.1.4 és IU 2025.1.7**, benne az új MCP-osztályok, a JDK HTTP-kiszolgáló és a csomagolt PDF kinyerése. Ez nem teljes Plugin Verifier vagy élő IDE-teszt.

A 8 oldalas magyar PDF megjelenítését, könyvjelzőit, MCP-fejezetét és a pluginba csomagolt példánnyal való azonosságát ellenőriztem. A panel 700 és 1000 pixel szélességű renderében a gombok elérhetők.

`./gradlew buildPlugin` itt a Gradle wrapper saját könyvtárába írt lockfájl tiltása miatt megállt. Az OS socketet használó teszteket a környezet tiltása miatt a helyi futtató `sb.repl.tests.noSockets=true` kapcsolóval hagyja ki. Normál Gradle/CI alatt ezek alapból engedélyezettek. A kézi IDE-indítás, valódi AI-klienssel felépített HTTP-kapcsolat és a Plugin Verifier még ellenőrizendő.

A **build/distributions/Spring-Boot-REPL-0.13.0-local.zip** telepíthető, helyi fordítókkal készített csomag; a név és a beágyazott buildleírás is jelzi az eltérő buildmódszert. Nem bizonyít sikeres Gradle-buildet. A csomag a meglévő `scripts/package-local.py` eljárással, a `build/mcp` alatt ellenőrzött fordításból készült; a futások naplói ugyanitt találhatók. A csomagokhoz SHA-256 ellenőrzőösszeg tartozik.
